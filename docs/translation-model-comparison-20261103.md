# 3.5 GB 内中日韩英翻译模型对比

日期：2026-11-03。12 个版本已完成主筛；用户已确认保留 Hy-MT2-1.8B Q6_K 为项目最终选型，生产默认保持一致。本文区分普通翻译的速度备选与满足完整术语需求的替代者，不强行给出通用冠军。

本轮比较完整任务的翻译质量和响应时间。正常 EOS 只表示生成结束，不能证明没有漏译或错译。以下语义结论来自编码助手逐项阅读原文和译文，不是独立人工标注、母语盲评或标准翻译质量分数。

## 目前可以确认的结果

- 单纯提高量化精度没有解决主要错译。Hy-MT2 Q8 仍把“不用等她开饭”反转；Qwen3.5 Q5 仍把花生译成核桃；TranslateGemma Q5 仍改错金额、币种和交付时间。
- Gemma4 E2B QAT Q4 是已测小模型中较有价值的速度备选，修正了 Hy 的若干事实错误，但术语组出现整句遗漏、未采用指定译法等问题。不能只凭普通翻译更流畅就宣布全面替代。
- 标准 Gemma4 E2B Q8 没有显示稳定的整体质量优势，实际响应更慢。它与 QAT 来自不同源权重，差异同时包含 QAT 和量化方案，不能把变化只归因于位宽。
- LFM2.5 的强制思考开销明显，仍有事实错误，并有两条长文本耗尽输出预算，不适合本项目的实时翻译目标。

**最终选型：保留现用 Hy-MT2-1.8B Q6_K。** 2026-11-03，用户根据本轮对比确认该决定，项目配置与分发程序继续采用现有模型。如果只需普通翻译、重视实时响应，Gemma4 E2B QAT UD-Q4_K_XL 可作为研究备选；它并没有通过现有全量术语场景。标准 Q8 和 7B 极低位量化不值得仅凭精度或参数量切换。此次没有找到在普通中日韩英、术语遵从和内容完整性上都稳定优于现用模型的版本。

可在[离线逐句对照页](translation-model-comparison-20261103.html)切换模型、原文、首轮和热态输出，直接核对事实。页面自包含，缺测项目明确显示未测试。

## 环境与显存口径

RTX 3050 6 GB，驱动 621.01；Ryzen 7 5700G；安装内存 32 GiB，系统可见约 29.95 GB。使用现有捆绑的 llama.cpp b11960 CUDA 构建，无 Python，无新生产运行依赖。环境与可执行文件 SHA-256 见 [environment.json](../.tools/benchmark/model-selection-20261103/environment.json)。

显存限制按严格 **3,500,000,000 bytes = 3.5 GB ≈ 3.260 GiB** 判断。测量目标进程的 Windows GPU `DedicatedUsage`，包括 GPU 权重、4096 上下文的 KV/状态、计算缓冲和运行开销；同时保存 `LocalUsage`、`SharedUsage`、整卡占用和原生 CUDA 缓冲日志。不能用 GGUF 文件大小替代显存。

GPU 采样约每 500 ms 一次，实际间隔随查询耗时记录；查询失败是未知值 `null`，不当作零。结果是采样峰值，不保证覆盖每个瞬时尖峰。ASR 单列，最终候选另做合载。

所有计算/输出层按 `--n-gpu-layers all` 加载至 CUDA，`--fit off`，不自动缩上下文、不回退计算层。Gemma4 的大 PLE 和普通输入词嵌入由原生实现保留为 CPU 内存映射，**不是全部参数都在显存**；其 36 个计算/输出层在 GPU。CPU 映射大小也不等于全部常驻物理 RAM。标准 Q8 文件约 5.05 GB，仍可能满足 GPU 显存限制。

## 初筛矩阵

统一为 4096 上下文、2048 输出预算、f16 KV、单 slot、Flash Attention auto、关闭 KV 提示缓存。主筛统一 greedy：temperature=0、top_p=1、top_k=0、repeat_penalty=1、presence/frequency_penalty=0、seed=42。各模型使用自己的模板，可关闭思考的模型关闭思考；LFM 官方始终思考，全部思考 token 与时间都计入任务。

表内耗时为固定 17 条各一次真实请求的跨例中位数，**不叫三次热态中位数**；LFM 的耗时仅对 15 条成功结束的请求取中位，另列两条失败。加载、内置预热均不在该任务耗时内。最终重复测速另见后表。

## 质量证据与取舍

以下只列可复核的例子，不用少数例子生成质量百分数。完整原文、检查项、每次译文与参数均有保存。

| 原意 | Hy Q6 | Gemma4 QAT Q4 | 标准 Gemma4 Q8 |
|---|---|---|---|
| 别等小美才开饭 | `她来之前不要开饭`，反转 | 不用等她，正确 | 不要等她来了才吃，正确 |
| 棕箱后天早上交付 | `the next morning`，时间错 | `the morning after tomorrow`，正确 | 同样正确 |
| 一次浇 150 mL，每周两次 | 改为每天 150 mL，与后句矛盾 | 未明确译“一次”，不算精确保留 | 具体作用域见逐项记录 |
| 12000 韩元阈值 | 数字保留，币种未明确 | 10000 韩元，错 | 10000 韩元，错 |
| 折后 25000 韩元 | 5000 韩元，错 | 12500 韩元，错 | 12500 韩元，错 |
| 第二站上车 | 保留站次 | 保留站次 | `二番線`，站次变站台/线路 |
| 11:30 前回不来，保留验证 | 10:30 才回来，错 | 修正时间 | 保留时间 |
| 只买三个梨，保留验证 | 泛化为三个水果 | 同样泛化 | 同样泛化 |
| 保留原文和译文，术语组 | 某例正确；另有跨目标语言污染 | 某例整句省略，另例新增只存原文 | 同样有整句省略；另例丢失原文与译文的对比要求 |

严格 `>30%` 与 `≥30%` 的边界变化单列，不能称作否定反转，也不与“停止变继续”同等处理。`four flights of stairs` 不严格等于四层楼，审阅按“四级台阶与四段楼梯”的实义区分；检查项中的简写不覆盖英语原文。合理转写、自然表述、重复强调省略与真正事实改写分别记录。

## 完整性、速度与合载

Hy Q6、Gemma4 QAT Q4 与标准 Q8 均完成普通 30 条及术语 5 条，每条首轮加三次热态，各 **140/140 正常 EOS**。已核对组内重复译文，不把重复运行当成新增独立样本。LFM 两个失败样本均已结束思考，但剩余预算不足以交付完整译文；不能拿思考中的草稿当作用户已收到的译文。7B 追加组在 17 条即暴露多个明确回归，没有按计划扩展为 35 条重复测试，也不伪造其热态或术语成绩。

下表为同一用例三次热态完整任务耗时中位数，单位秒。每次都重新提交同一输入，`cache_prompt=false`，不是从 KV 复用中取巧。统计包含模板、分词、本地 HTTP 推理和解码，不含模型加载或 ASR。

| 用例 | Hy Q6 | Gemma4 QAT Q4 | 标准 Q8 |
|---|---:|---:|---:|
| 短句中→英 | 0.191 | 0.193 | 0.306 |
| 日期安排中→日 | 0.876 | 0.908 | 1.565 |
| 家庭用餐中→韩 | 1.335 | 1.189 | 2.031 |
| 长交接安排中→英 | 3.800 | 3.705 | 6.440 |
| 长维护安排中→日 | 5.415 | 3.756 | 6.535 |

普通 30 例的“每例三热中位数再跨例取中位”为 Hy **1.321 秒**、QAT **1.037 秒**、标准 Q8 **1.729 秒**。不同 tokenizer 和译文长度会改变 token 数，不能将任务耗时差直接解释成纯解码速度差。例如长日语用例分别为 427/286/291 个生成 token，原始记录保留了具体译文供检查是否变短是因为遗漏。

单次加载加内置预热：本轮普通组 Hy 1.204 秒、QAT 2.574 秒、标准 Q8 2.159 秒。未清空操作系统文件缓存，不称冷磁盘测试；这些是单次观察，不用来推导稳定启动速度排名。完整重复组专用显存峰值分别为 **1.895 / 1.567 / 2.834 GB**。具体首轮、三热最小/中位/最大、输入输出 token 见 [final-summary.json](../.tools/benchmark/model-selection-20261103/final-summary.json)。

ASR 使用生产同款 Fun-ASR-Nano BF16 与原生 CUDA 库：先识别已有 9.122 秒 WAV，随后保持模型和 session 常驻，再顺序测试 LLM。没有录制麦克风，没有更改服务接口。首组 ASR 专用显存峰值 **2,003,529,728 B**。三组各 5 例、首轮加三热全部完成；Hy/QAT 首组合载的整卡峰值 **5,007,998,976 B**，标准 Q8 第二组合载峰值 **6,009,389,056 B**。整卡值包含桌面等其他进程，不能当成两个模型净占用之和。

合载时长日语用例热态中位为 Hy **5.428 秒**、QAT **3.771 秒**、标准 Q8 **6.557 秒**，与各自单独测速接近；专用/共享显存及全部合载时长见 [coload-summary.json](../.tools/benchmark/model-selection-20261103/coload-summary.json)。这只是模型常驻、顺序推理验证，不等于完整 HTTP 音频流水线回归。

## 提示与推荐参数控制

主筛统一使用项目原有中文完整性指令，TranslateGemma 使用自己的官方源/目标语言专用模板，源语言来自固定语料元数据。额外固定六条非中文互译做英文指令敏感性对照，保持 greedy。另对 Hy、Gemma 做 17 条推荐采样对照，对 Qwen/LFM 做六条推荐采样对照；不把各组每条最优译文拼成分数。

Hy 模型卡推荐 0.7/0.6/20、重复惩罚 1.05；Gemma4 官方推荐 temperature=1、top_p=0.95、top_k=64。本机此组随机采样没有普遍修好事实错误，Gemma QAT 还出现原样返回日文的未翻译输出，因此完整重复组仍固定 greedy。模型推荐参数不等于每种任务的准确率保证。[Hy 官方模型卡](https://huggingface.co/tencent/Hy-MT2-1.8B-GGUF)、[Gemma4 官方最佳实践](https://ai.google.dev/gemma/docs/core/model_card_4#best-practices)。

LFM 是官方始终思考的模型，不能用不存在的关闭思考开关伪造低延迟。其推荐 0.1 温度、top_k=50、重复惩罚 1.1 的六条对照仍记录全部思考时间。[LFM 官方说明](https://huggingface.co/LiquidAI/LFM2.5-2.6B/blob/b212e75975bbda9676a94d3cb7b2ca25b65fed48/README.md)。

术语组每次均使用相同完整七行表、全部语言，不分词、不按源句筛词。此处关闭缓存以对齐评测，不能代表新模型已通过大术语表 KV 复用压力测试。TranslateGemma 没有本项目同类术语指令接口，其普通翻译成绩也不能直接证明兼容现有术语功能。

## 复现与限制

- [固定方法](../.tools/benchmark/model-selection-20261103/evaluation-plan.md)；[35 条原文与 240 项事实检查](../.tools/benchmark/model-selection-20261103/cjk-cases.jsonl)；[完整术语表](../.tools/benchmark/model-selection-20261103/glossary.tsv)。涵盖中、日、韩、英的 12 个有向翻译方向，分布不均，每方向样本很少，不代表全面语言能力。
- 15 条旧例保留，新增 20 条先冻结再运行。八条为本次流程上的保留复核，作者和执行助手可以看到语料，不声称独立盲评。后追加 7B 候选属于探索性扩展，不能再宣称旧保留集对该选型过程完全未见。
- 所有候选权重从 ModelScope 下载，固定 revision、长度与 SHA-256，第三方量化与发布作者文件元数据对照。收据保存在同一评测目录；模型不加入 dist。来源与架构推算见[通用模型研究](../.tools/benchmark/model-selection-20261103/research-general.md)、[翻译模型研究](../.tools/benchmark/model-selection-20261103/research-translation.md)。
- [compare_llm.rs](../examples/compare_llm.rs) 独立运行，不修改生产 LLM。`run-screen.ps1` 支持指定用例、模型、采样、英文控制、完整术语与重复次数；`run-coload.ps1` 使用 [hold_asr.rs](../examples/hold_asr.rs) 做合载。结果使用 create_new，重跑用新标签保存，不覆盖旧输出。
- 初版评测程序遗漏自动 BOS，TranslateGemma/Gemma4 的旧无 BOS 文件仅保留诊断。正式比较使用修正后结果。逐字符核查排除了换行转义错误；分词对照确认只补一次 BOS、不多加 EOS。Hy/Qwen 不受此遗漏影响。说明与固定 llama.cpp 源码证据见逐项报告。
- 生产默认、服务接口和 dist 可执行文件保持现有 Hy Q6；这份对比没有完成新模型的生产集成、全部 HTTP/录音回归或大术语表缓存验证，不将独立基准冒充上线验证。
- 工作区测试、fmt 与 Clippy 已通过；原有需要额外模型/音频资源的 ignored 测试不计为通过。新基准 15 项 CPU 测试、ASR 常驻工具 2 项 CPU 测试通过；模型 GPU 实测另有完整 JSONL 记录。
- 离线对照页已在实际浏览器验证：320px 单列无横向溢出、900px 双列、目标语言与术语筛选、轮次与失败/缺测显示。页面不使用外部脚本或资源；全部模型数据内嵌，打开文件不需要启动本项目服务。
