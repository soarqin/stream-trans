# 进程内 llama.cpp 验证（2026-11-07）

Windows 服务改为由 Rust 加载固定构建的 `llama-server-impl.dll`，通过项目补充的 ABI 1 管理服务线程。发行目录不再包含 `llama-server.exe`；Linux 继续使用已有 CLI 路径。

## 实现与边界

- C ABI 提供版本、创建、运行、停止、状态、销毁六个入口，避免跨语言依赖 C++ 名称修饰和 `common_params` 布局。
- 不调用 CLI 主入口，不解析 `LLAMA_ARG_*`、`LLAMA_API_KEY` 或 AIP 环境配置，不修改信号处理、工作目录或 locale，也不重定向标准输入输出。
- 保留原有回环 HTTP、随机内部 API key、分词、完整术语前缀和 KV 缓存。ASR 与翻译共享同一份 ggml CPU/CUDA 后端，GPU 工作仍串行调度。
- 停止时取消加载/请求并等待服务线程退出，释放模型；DLL 与后端目录保留至进程退出，避免共享注册表或回调引用已卸载代码。
- CUDA 只能在加载进度及请求批次/令牌边界协作取消，不能硬抢占任意内核。超时返回前等待原生工作结束，因此不再具备子进程的强制终止和崩溃隔离能力。
- llama 自身只保留 WARN/ERROR 日志，避免逐令牌调试日志进入控制台；不替换 ASR/ggml 的全局日志回调。

## 复测条件

RTX 3050 6 GB、驱动 621.14；Ryzen 5700G；ASR BF16、Hy-MT2-1.8B Q6_K，llama.cpp b11960，CUDA 12.8。模型、音频、目标语言和采样参数不变；KV=f16、上下文 4096、最大输出 2048、seed=42、temperature=0.7、top-p=0.6、top-k=20、repeat-penalty=1.05。

旧版对照为 `dist/StreamTrans-shared-ggml`。测试从 `C:\Windows\Temp` 启动，PATH 仅含 System32。输入为 16 kHz 单声道 PCM16 的 9.122 秒合成中文，翻译为英文。加载及内置预热、首轮、额外一轮预热与四次正式请求分别记录；不将加载计入请求延迟。

原始测试记录保存在本机 `.tools/embedded-server-probe/`，不随仓库提交。后续表格和分发回执只记录最终构建的实测结果。

## 性能与等待策略

Windows 启动在加载模型前对同一套 `cudart64_12.dll` 显式设置 `cudaDeviceScheduleSpin`，保留其他 flag，并读取结果确认。ASR、LLM 及 Rust 基准入口共用此配置。它只改变主机等待 GPU 的方式，不修改权重、KV 精度、采样、提示词或计算图；等待期间会增加 CPU 占用。[NVIDIA CUDA 12.8 设备管理说明](https://docs.nvidia.com/cuda/archive/12.8.1/cuda-runtime-api/group__CUDART__DEVICE.html)。

模型缓存校验、加载和内置预热单独计时：旧版重启从缓存校验日志到 HTTP 就绪约 7.48 秒；Spin 首轮约 6.25 秒，不计入上表请求耗时。该阶段受文件缓存和当时系统负载影响，不据此宣称加载速度提升。独立 LLM 基准也分别记录 `load_and_builtin_warmup_ms`、首请求及热态。

Auto 的回退确实存在，但未认定其完整驱动层根因。对运行中的进程进行 10 秒、50 ms 间隔的 WDDM 查询，共 200 帧：本地使用峰值 3676 MiB、最低预算 4217.211 MiB、最少余量 541.211 MiB、超预算 0 帧；非本地使用全程 102 MiB。该窗口不支持「持续超预算」解释，也不能据此排除所有驻留或调度因素。反序加载及请求间隔未消除回退，因此没有用这些办法作为修复。

## 接口与生命周期验证

- 默认模型及本机 CUDA 实测：ASR 为 CUDA0；LLM 状态回执确认指定 CUDA 设备实际承载全部 33/33 层，随后核验 Hy-MT2 特殊 token ID。
- 从项目外目录及最小 PATH 启动；将 `LLAMA_ARG_MODEL`、GPU 层数、端口、`LLAMA_API_KEY`、`AIP_MODE` 设为冲突值，固定项目参数仍生效。
- 文件接口：中文转英文、中文转日文、英文转中文；18.244 秒中文仅 ASR 正确返回四段、`translation:null`。八种音频格式/布局的识别结果及两段 VAD 边界一致。
- WebSocket 真实时长连续发送：仅 ASR 和翻译均在客户端发送 `finish` 前返回首段，最终各两段。Spin 日语模式首原文约 5.443 秒、首译文约 5.885 秒，约 9.674 秒完成；保留录音结束前结果断言。
- 五条完整术语表、三组 CJK/英文方向，共 12/12 次翻译通过严格 EOS/完整性校验；完整前缀 128 token，同句复用 203 个 prompt token，换目标语言仍复用 133 个。术语遵从和语言混入的已知模型限制未因此消除。
- C ABI 自检：拒绝错误结构/版本，停止幂等，先停止再运行可安全结束，禁止同一 handle 二次运行，连续销毁/创建正常。真实模型加载中取消后，可在同一进程重新加载并翻译两次。
- 推理超时测试：请求停止并等待原生线程结束，报告后端已停止，未把部分译文计为成功。CUDA 取消有协作等待，不承诺在设定秒数到达时立即返回。
- 正常 Ctrl+C 后服务进程、内部端口均退出，没有待清理的 llama/FFmpeg 子进程。
- 常规 Rust 测试 110 项通过；另执行两项原生生命周期测试及一项默认 Hugging Face ASR 转换字节一致性测试，均通过。格式检查、Clippy、PowerShell 5.1 分发布局自检通过。
